# 仓库测试门禁

## 核心原则

**修改代码必须对测试负责。** 不允许只保证生产代码正确，却留下因本次修改而失效的测试。

本规范适用于所有编程语言。纯文档修改不强制执行测试。

## 提交前验证

1. 开发过程中可以优先运行局部测试，快速定位问题。
2. 提交前默认执行仓库规定的全仓自动测试入口。
3. 若仓库没有统一入口，应执行能够确认的现有测试集合，并如实说明未覆盖范围。
4. 测试失败必须调查原因，不得直接忽略。

## 测试断言的稳定性

测试应验证功能契约，而不是容易变化的数据现状。

- 严禁对经常增删的配置字典、资源列表等数据写死元素数量、完整键集合或排列顺序。
- 测试应优先验证数据结构、合法性、输入输出及实际业务行为。
- 功能测试应尽量使用独立构造的测试数据，避免依赖生产配置的当前内容。
- 只有数量、顺序等本身属于明确的业务契约时，才允许进行相应的固定断言。

## 测试失败的处理

- **生产代码错误**：修复生产代码。
- **测试预期过时**：确认新行为正确后，同步更新测试代码。
- **既有测试失败**：尽可能与修改前的基线比较，区分历史问题与本次引入的问题。
- **测试环境故障**：遵守现有环境规范，不得擅自安装依赖、修改环境或创建环境。

严禁仅为了让测试通过而删除有效用例、放宽断言或随意跳过测试。

完成修复后，必须重新运行相关测试及全仓测试。

## 本地测试留痕

测试过程中产生的截图、录屏、临时报告等留痕产物，不得提交到 Git，统一保存至主 Worktree 根目录下的 `本地测试留痕/`。

- **存放位置**：不得保存到 `本地测试留痕/` 以外。应在该目录下建立两层子目录，首层子目录为被测试对象简称，二层子目录为具体任务简称。
- **Worktree 隔离**：通过 `git worktree list --porcelain` 定位主 Worktree。临时 Worktree 中的测试应直接向主 Worktree 输出留痕；无法直接输出时，可保存到临时 Worktree 中。
- **Git 屏蔽**：必须确认留痕目录已被 Git 忽略。
- **保留与清理**：由用户自行决定清理时间。未经授权不得自动删除。

## 提交门禁

- 本次修改引入的测试失败未解决时，不得将任务视为完成。
- 只有项目明确规定或用户明确授权，才能免除本地全仓测试。由 CI 承担全仓测试时，必须在合并前确认结果。
- 无法完成验证时，必须报告原因和已验证范围，不得声称测试通过。
- 交付时应说明测试命令及实际结果。
