#### 核心定位与原则

Mixin（混入类）是一种通过多继承为目标宿主类提供特定功能片段的解耦手段。它不负责实例化独立对象，也不应维护独立于宿主类之外的复杂初始化流程。

使用 Mixin 时必须遵循以下两条硬性规范：

- **Mixin 尽量保持无状态**：Mixin 应该只提供纯方法行为，其所依赖的状态全部来自于宿主类（由宿主类的 `__init__` 统一初始化）。否则，极易打断多继承的初始化参数链。如果 Mixin 必须做初始化，推荐提供显式命名的配置方法（例如 `api_初始化_状态通知()`），由宿主类的 `__init__` 在内部显式调用，而不是在 Mixin 里强行写 `def __init__()`。
- **正交设计**：Mixin 之间严禁相互继承和耦合。
- **顺序严格对齐**：多继承时 Mixin 类必须全排在前面（左侧），从而将带有实体 `__init__` 的主基类排在最后面（右侧）。
- **显式宿主类型提示**：Mixin 内部方法在访问宿主属性或方法时，必须对 `self` 显式标注宿主类类型（使用 `if TYPE_CHECKING:` 导入，并在类型提示时使用双引号包裹类名），以提供完整的 IDE 重构与静态类型分析能力。

类型提示的策略如下：

```python
if TYPE_CHECKING:
    from xxx import 宿主_类

class 某个_Mixin_类:
    def api_执行某项功能(self: "宿主_类", arg_参数: str) -> bool:
        # 此时 IDE 可以完整识别 self 上的宿主属性
        return self.内部状态 == arg_参数
```
