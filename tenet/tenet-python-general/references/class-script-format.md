# Python class 与脚本格式参考

本参考保存 `python-general` 中不适合压缩成一句话的结构范例、理由和反模式。它不是另一套规则；正文中的硬规则仍然优先。

## 标准 class 范例

```python
class 这是一个示例_类:
    """
    说明这个 class 的功能、职责和必要背景。

    更新日志：
    2026.10.07 - 建立。
    """

    def __init__(
        self,
        arg_参数1: str,
        arg_参数2: int,
        arg_实例A: "示例_类",
    ) -> None:
        """
        Args:
            arg_参数1: 只有名称与类型仍不足以解释时才写。
            arg_参数2: 同上。
        """
        self.参数1 = arg_参数1
        self.参数2 = arg_参数2
        self.实例A = arg_实例A

    def api_写入_x_轴坐标(self, arg_x_轴坐标: int) -> tuple[bool, str]:
        """
        将 x 轴坐标写入目标数据。

        Returns:
            返回是否成功，以及必要的结果说明。
        """
        ...

    def _内部方法(self) -> None:
        ...
```

这个范例表达的是几个长期约定：

- 项目自有 class 名称以 `_类` 或 `_基类` 结束。
- class 对外稳定方法用 `api_` 标出；内部实现不应伪装成公开 API。
- 入参数量不少于三个时，每个参数独占一行。
- 依赖注入时优先直接使用真实 class 做类型提示；为了避免循环引用，可以使用字符串形式的前向引用。
- class 的 docstring 同时承担功能说明和更新日志职责。
- 参数与返回值注释只补充“命名 + 类型”无法表达的信息，不做重复翻译。

## 更新日志为什么不能换行

更新日志采用 `YYYY.MM.DD - 内容。` 的单行结构。即使内容较长，也不能把同一条记录拆成多行。

正确：

```python
class 示例_类:
    """
    示例。

    更新日志：
    2026.10.07 - 调整项目加载流程并统一入口调用。
    """
```

错误：

```python
class 示例_类:
    """
    示例。

    更新日志：
    2026.10.07 - 调整项目加载流程。
        同时统一入口调用。
    """
```

原因不是单纯追求整齐：仓库中存在自动程序解析更新日志。跨行记录会破坏解析，因此这是机器契约。

## `arg_` 前缀的语义

`arg_` 用来标定“这是从 def 调用入口传入的数据”。它能让维护者在较长方法中快速识别数据来源和流向，同时形成一个自然的类型提示检查点。

因此：

```python
def api_读取(self, arg_路径: str) -> str:
    ...
```

而把入参保存为实例状态后，不应继续写成：

```python
self.arg_路径 = arg_路径  # 反模式
```

应写成：

```python
self.路径 = arg_路径
```

因为 `self.路径` 已经是对象内部状态，而不是“调用入口参数”。

### 第三方 override 是明确例外

如果继承第三方库并重写其既定接口，方法名和参数名必须忠实于第三方契约。例如 PySide6：

```python
def keyPressEvent(self, event: QKeyEvent) -> None:
    ...
```

不要为了仓库内部命名规范写成：

```python
def keyPressEvent(self, arg_event: QKeyEvent) -> None:  # 不推荐
    ...

def keyPressEvent(self, arg_事件: QKeyEvent) -> None:  # 不推荐
    ...
```

此时保持第三方接口原样比强行中文化或添加 `arg_` 更重要。

## 标准脚本骨架

```python
# ◑ 导入
import os

from PySide6.QtWidgets import (
    QApplication,
    QMainWindow,
    QPushButton,
    QVBoxLayout,
    QWidget,
)


# ◕ 功能
class 示例_类:
    """
    示例功能。

    更新日志：
    2026.10.07 - 建立。
    """

    def api_执行(self) -> None:
        ...


# ◍ 运行
if __name__ == "__main__":
    示例器 = 示例_类()
    示例器.api_执行()
```

三个区域的含义：

1. `# ◑ 导入`：所有 import。
2. `# ◕ 功能`：class 与函数定义。通常一个脚本只保留一个主要 class；少数纯入口脚本可以没有 class。
3. `# ◍ 运行`：只有脚本确实需要直接运行时才存在。

如果没有直接运行代码，就连 `# ◍ 运行` 标题一起删除。禁止留下空的运行区。

从同一模块导入超过三个对象时，用括号换行形式，避免一行塞入大量名称。

## `__init__.py` 默认留空

本仓库不通过 `__init__.py` 做无必要的 re-export。

不要为了“看起来方便”增加：

```python
from .某功能_入口 import 某功能_入口_类

__all__ = ["某功能_入口_类"]
```

调用者应直接 import 正式定义所在脚本。这样能够显式暴露真实依赖位置，减少大型单体仓库中的隐式转发和兼容层。

## 历史代码不是格式教材

生产代码可能早于当前规范建立，因此会存在旧格式。维护旧文件时可以渐进治理，但新建或重写当前任务直接涉及的代码，应以当前 Skill 为准，而不是复制旧文件的历史格式。
