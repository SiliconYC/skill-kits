# Python 内聚组件局部组织规范

## 核心原则

内聚组件的局部结构遵循三条刚性规则：

1. **单一入口**：组件根目录下只保留唯一的入口脚本，对外只暴露门面，避免在根目录平铺兄弟业务脚本。一个最理想的设计是在内部组件根目录下只保留入口脚本和 `README.md`。
2. **实现全面下沉**：所有具体实现全部折叠收拢至一个或多个功能型子目录，例如 `mod/`、`A_管理/`、`impl_功能/` 等。测试目录也是一个功能性子目录。
3. **积极使用目录嵌套**：避免扁平化平铺。例如 `impl_功能/` 内部必须按职责继续拆分子目录，保持深度组织。

## 典型目录结构

```text
组件目录名/
├─ README.md  # 组件说明
├─ 组件名_入口.py  # 唯一入口脚本（门面）
├─ A_管理/  # 管理与装配，可能有更多嵌套结构，此处省略
│   ├─ 适配器.py
│   └─ 组装工厂.py
├─ C_交互/  # 表现与交互，可能有更多嵌套结构，此处省略
│   ├─ 控制器.py
│   ├─ 界面.py
│   └─ 组件名_快捷键集成.py
└─ impl_持久测试/  # 测试目录，目录内部同样有嵌套结构
    ├─ 测试_入口.py
    ├─ 某测试功能_A/
    └─ 某测试功能_B/
        └─ ...其它测试脚本.py
```

## 引用规范

- **类型提示隔离**：仅用于类型注解的导入，一律放入 `if TYPE_CHECKING:` 块内。
- **明确相对导入**：组件内部各脚本之间一律使用相对导入（`.` 或 `..`），不使用从项目根目录开始的长绝对路径。
