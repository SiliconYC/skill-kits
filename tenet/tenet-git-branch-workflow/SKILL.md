# 本地 AI Agent 的 Git 分支工作流

接手任务准备修改代码前，你的第一件事是判断当前工作区处于哪一个 Git 分支。不同分支决定了你后续应该如何提交、是否需要合并、以及是否需要同步到 GitHub。

## 第一步：识别当前工作区分支

执行 `git branch --show-current` 和 `git status --short`，将当前所在的本地分支归入以下两大类之一（若处于无分支名的游离 HEAD 状态，直接停下来询问用户）：

1. **四大永久分支**：`main`、`dev`、`smart`、`golden-gate`
2. **非永久分支（现成临时分支）**：除上述四大永久分支以外的所有分支

确认分类后，严格按对应的工作流执行，无需向用户请示常规步骤，仅在遇到异常或冲突时停下来询问。

---

## 工作流 A：当前位于【四大永久分支】

`main`、`dev`、`smart`、`golden-gate` 均在 GitHub 上有远端备份，要求本地与 GitHub 保持严格同步，且**禁止直接在永久分支上修改和提交代码**。

当你发现当前工作区处于这四个永久分支之一时，必须按以下顺序自动走完全流程：

1. **拉取 GitHub 最新代码**：先检查当前工作区是否有未提交的修改。
  * 若工作区干净，直接执行 `git pull --ff-only` 将 GitHub 上的最新代码同步到本工作区。
  * **冲突中断点**：若工作区原本就有未提交的修改，拉取远端极易引发冲突，此时**立即停下来询问用户如何处理**，不得擅自丢弃、暂存（stash）或覆盖已有修改。
2. **派生本地临时分支**：基于同步后的当前永久分支，派生并切换到一个新的临时分支（例如 `git switch -c tmp/<任务简述>`）。
3. **在自建临时分支上开发与测试**：在这个新派生的临时分支上进行编程、测试和本地提交（`git commit`）。该临时分支仅作本地过渡使用，**严禁将其推送到 GitHub**。
4. **主动合回原永久分支**：测试全部通过后，切回接手任务时所在的**原永久分支**（从哪个永久分支派生，就必须交还给哪个永久分支），将刚刚派生的临时分支合并进来（`git merge`），随后删除该本地临时分支（`git branch -d`）。
5. **同步到 GitHub 并交付验收**：将合并后的原永久分支推送至 GitHub（`git push`）。确认推送成功、且当前工作区已稳妥停留在原永久分支后，再通知用户进行检测验收。
* **冲突中断点**：若合并时发生代码冲突，或向 GitHub 推送时因远端版本变动导致推送失败，**立即停下来询问用户解决方案**，严禁使用 `--force` 强制推送。

[!warning] 严禁停在自建临时分支上让用户验收。由你从永久分支派生出来的临时分支，用户是找不到对应工作区的。开发测试完成后，绝对不允许停留在你自建的临时分支上让用户去检测；必须先合入原先的永久分支、恢复工作区所在分支并完成 GitHub 同步，最后才能通知用户验收。

---

## 工作流 B：当前位于【非永久分支（现成临时分支）】

当你接手工作区时，发现它本身就已经处于一个非永久分支（现成的临时分支），说明用户直接交给你的是一个局部开发环境。这类分支通常没有在 GitHub 上同步，贸然同步也没有意义。

请忽略其他分支的存在，直接按以下规则处理：

1. **直接接手现有代码**：直接在当前工作区已有的代码基础上进行编程开发，保留工作区原有的合理改动。
2. **本地测试与原地提交**：编程和测试完毕后，直接将代码提交（`git commit`）到当前工作区所在的这个临时分支即可。
3. **不派生、不合并、不同步**：除非用户另有明确指令，否则**不需要**再派生新分支，**不需要**与其他任何分支合并，也**不需要**拉取或推送到 GitHub。本地提交完成后，即可直接通知用户检测验收。

---

## 核心行为对照表

| 接手时的当前分支 | 是否拉取远端 | 开发与提交位置 | 是否合并 | 是否推送到 GitHub | 最终交付时的所在分支 |
| --- | --- | --- | --- | --- | --- |
| **四大永久分支** (`main` / `dev` / `smart` / `golden-gate`) | 先拉取最新代码（有未提交改动则先问用户） | 派生新的本地临时分支进行开发、测试与提交 | 测试后必须合回原永久分支 | 必须将原永久分支推送到 GitHub（临时分支绝不推送） | 必须回到**原永久分支**再通知用户验收 |
| **非永久分支**（其他现成临时分支） | 不拉取 | 直接在当前临时分支原地开发、测试与提交 | 不合并 | 不推送 | 保持在**当前临时分支**直接通知用户验收 |
