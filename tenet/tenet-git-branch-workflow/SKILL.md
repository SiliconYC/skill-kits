# 本地 AI Agent 的 Git 分支工作流

接手开发任务前，必须依次判定当前工作区的物理身份与所在分支类型。不同的工作区和分支状态，决定了后续的代码开发位置、提交规范、集成方式以及远端同步策略。

---

## 核心原则：受保护主工作区不可侵占

### 1. 受保护工作区界定

满足以下任一条件的工作区即属于**受保护工作区**：

- Git 主工作区（`git worktree list --porcelain` 中的首个根工作树）。
- 处于核心永久分支（本规范指定为 `main` 或 `dev`）的工作区。
- 与 Git 仓库同名的本地主目录。

### 2. 核心红线

- **分支冻结**：受保护主工作区绑定的永久分支绝对固定。严禁在该目录下执行 `git switch`、`git checkout` 或任何切换、派生分支的操作。
- **物理隔离与拓扑规范**：从永久分支派生任务时，必须使用 `git worktree add -b` 创建独立目录与临时分支。派生工作区须遵循**同级并置原则**（置于原工作区同一父目录下的同级目录），严禁在主工作区原地开发，严禁将派生工作区嵌套在主工作区内部，严禁直接在永久分支上提交开发性代码。
- **状态纯净**：主工作区仅用于同步远端、验证集成结果和执行快进合并。主工作区严禁残留未提交修改、暂存区改动、冲突文件或未完成的半成品。
- **禁止异常合理化**：若主工作区接手时已处于临时分支、游离 HEAD 或存在未提交修改，属于异常状态，必须立即停机保全现场并报告用户。严禁擅自执行 `reset --hard`、`clean -fd`、`stash`、强制切换分支，严禁将异常状态的主工作区套用工作流 B。

## 第一步：环境识别与分支判定

执行以下检查命令：

```bash
git rev-parse --show-toplevel
git worktree list --porcelain
git branch --show-current
git status --short
```

根据命令输出进行分类匹配：

| 匹配状态 | 判定分类 | 后续动作 |
| :--- | :--- | :--- |
| 主工作区 + 分支为 `main` 或 `dev` | **永久分支** | 执行 **工作流 A** |
| 独立的临时 Worktree + 非永久分支 | **现成临时分支** | 执行 **工作流 B** |
| 主工作区处于非永久分支 / 游离 HEAD / 存在未提交修改 | **环境异常** | **立即中断**，保留现场并报告用户 |

## 工作流 A：永久分支开发流

永久分支与 GitHub 远端保持严格同步，**严禁原地修改与提交**。所有开发必须在独立 Worktree 中闭环完成，最后经由集成验证后快进同步回永久分支。

```
[父级根目录]
   ├── [受保护主工作区] (main/dev)
   │        │ (1. pull --ff-only)
   │        │ (2. worktree add -b 同级派生)
   ├──► [同级开发 Worktree] (tmp/task-xxx) ──► 编码、本地测试、commit
   │        │                                       │
   │        │ (4. worktree add -b 同级派生)          ▼
   └──► [同级集成 Worktree] (tmp/integ-xxx) ◄───────┘ (合并任务分支、测试验证)
            │                               │
            │ (5. merge --ff-only & push)   ▼
   [受保护主工作区] ◄────────────────────────┘
            │
            │ (6. 移除临时 worktree 和分支)
            ▼
     [通知用户验收]
```

### 详细步骤

1. **检查与同步**
   - 检查主工作区是否干净（`git status --short` 必须为空）。若存在未提交改动，立即中断并向用户确认，严禁擅自丢弃或暂存。
   - 状态干净时，执行快进同步：`git pull --ff-only`。不得为了同步而切换分支。
2. **派生独立开发 Worktree**
   - **路径同级并置原则**：新建工作树物理目录必须与主工作区置于同一父目录之下，作为**同级目录**并列放置。严禁将派生工作树嵌套存放在主工作区内部。
   - 基于同步后的永久分支创建独立目录与本地分支：

     ```bash
     # 示例：主工作区位于 path/to/project，派生到同级目录 path/to/project-task-xxx
     git worktree add -b tmp/<任务名> ./<主工作区目录名>-tmp-<任务名> <原永久分支>
     ```

   - 临时分支名与路径须保持全局唯一，严禁在主工作区直接派生分支。
3. **隔离开发与测试**
   - 仅在新建的同级 Worktree 目录内进行代码编写、本地测试与 `git commit`。
   - 临时分支仅用于本地过渡，**严禁推送到 GitHub**。主工作区保持在原永久分支不动。
4. **隔离集成与验证**
   - 任务测试通过后，同样依同级并置原则，从原永久分支的最新状态派生独立的集成 Worktree（例如 `./<主工作区目录名>-tmp-integ-<任务名>`）。
   - 在集成 Worktree 中合并任务分支并运行全量验证；如遇代码冲突，**必须在集成 Worktree 内解决**，严禁在主工作区处理冲突。
   - 若原永久分支或远端已有更新，先在集成 Worktree 中纳入最新基线并重新验证。
5. **快进合回与推送**
   - 确认主工作区保持干净，以单写入者方式将验证通过的集成分支快进合并入永久分支：

     ```bash
     git merge --ff-only tmp/<集成任务名>
     git push
     ```

   - 坚持“从哪个永久分支派生，合回哪个永久分支”；合并期间主工作区全程不切换分支。
6. **收尾清理与交付**
   - 确认 `git push` 成功且主工作区状态完全干净后，清理临时资源：

     ```bash
     git worktree remove <开发Worktree路径>
     git worktree remove <集成Worktree路径>
     git branch -d tmp/<任务名>
     git branch -d tmp/<集成任务名>
     ```

   - 清理完成后，通知用户验收。

### 并发与异常处理

- **并发写入保护**：多个 Agent 并发作业时，对永久分支的快进与推送必须串行执行。推送前须重新核验最新状态；若远端已被推进，须退回集成 Worktree 重新集成与验证，严禁直接覆盖他人提交。
- **冲突中断点**：若集成无法自动解决、快进合回失败或推送被拒，保留相关 Worktree 现场，严禁使用 `--force` 强制推送，排查无法收口时立即报告用户。

> [!warning]
> 严禁让受保护主工作区停留在临时分支，严禁在未完成清理前交付用户。

## 工作流 B：现成临时 Worktree 开发流

当且仅当当前环境为**独立的临时 Worktree**且处于**现成临时分支**时，表明用户已搭建好局部工作空间，适用此轻量流程。

### 详细步骤

1. **就地接手**：直接在当前独立 Worktree 中基于现有代码开发，继承原有的有效改动。
2. **原地提交**：完成编码与测试后，直接在当前分支执行本地提交（`git commit`）。
3. **就地交付**：除非用户明确要求，否则**不派生新分支、不合并到其他分支、不拉取或推送到远端**。本地提交完成后直接通知用户验收。

---

## 核心行为速查表

| 接手工作区与分支状态 | 远端拉取 | 开发与提交位置 | 合并与验证 | 远端推送 | 最终交付状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **受保护永久分支** (`main`/`dev`) | 主工作区干净时 `pull --ff-only` | 同级独立 Worktree | 同级集成 Worktree 验证，主工作区仅快进合入 | 仅推送永久分支，严禁推送临时分支 | 主工作区干净并停留在永久分支；临时 Worktree 与分支全部清理完毕 |
| **独立临时 Worktree** (临时分支) | 不拉取 | 当前 Worktree 原地开发与提交 | 不执行合并 | 不推送远端 | 保持当前分支与提交，直接通知用户验收 |
| **主工作区异常** (处于临时分支/游离HEAD/脏修改) | 暂停一切操作 | 严禁继续开发 | 严禁常规合并 | 严禁推送 | 保全现场，向用户汇报并等待明确指令，禁止套用工作流 B |
