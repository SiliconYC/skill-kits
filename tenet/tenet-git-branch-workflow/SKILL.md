# 本地 AI Agent 的 Git 分支工作流

接手任务前，先执行环境检查：

```bash
git rev-parse --show-toplevel
git worktree list --porcelain
git branch --show-current
git status --short
```

---

## 决策路由表

根据检查结果匹配执行流：

| 当前环境 | 分支状态 | 工作区状态 | 执行策略 |
| :--- | :--- | :--- | :--- |
| **主工作区** | `main` 或 `dev` | 干净 | **工作流 A**（正常执行拉取与同级派生） |
| **主工作区** | `main` 或 `dev` | **存在未提交修改 / 暂存区非空** | **工作流 A**（按未提交保护规则处理） |
| **独立 Worktree** | 临时分支 | 任意 | **工作流 B**（就地开发提交，不推送） |
| **主工作区** | 非永久分支 / 游离 HEAD | 任意 | **环境异常**：立即中断，保留现场并报错 |

---

## 核心红线

1. **主工作区冻结**：严禁在受保护的主工作区内切换分支、直接编码或直接 commit。
2. **绝对保全现场**：主工作区存在未提交修改或暂存区内容时：
   - **严禁**擅自替用户 `git commit`。
   - **严禁**擅自执行 `stash`、`reset --hard`、`checkout -- .` 等丢弃操作。
3. **冲突分级响应（关键）**：
   - **静态冲突（已提交代码间冲突）**：Agent 在临时分支内**自行解决**，禁止打扰用户。
   - **动态冲突（合并动作与主工作区未提交/暂存区修改冲突）**：**唯一允许且必须停机向用户询问的场景**。

---

## 工作流 A：永久分支开发流（主工作区）

核心逻辑：**主工作区不动，同级 Worktree 隔离开发，测试通过后合回并推送。**

### 1. 确认基线

- 若主工作区干净：执行 `git pull --ff-only` 更新代码。
- 若主工作区有未提交修改/暂存内容：**不提交、不丢弃**，以本地已提交的最新历史（`HEAD`）为派生基线。

### 2. 派生同级 Worktree

新建 Worktree 必须与主工作区置于**同一父目录下作为同级目录**，严禁嵌套在主工作区内：

```bash
# 基于最新已提交基线同级派生（假设主目录名为 my-project）
git worktree add -b tmp/<任务名> ./my-project-tmp-<任务名> <原永久分支>
```

### 3. 隔离开发与验证

- 在 Worktree 内完成编码与调试。
- 提交前必须执行 `tenet-repository-test-gate`，完成测试验证及失败处理。
- 验证通过后执行 `git commit`。
- 若后续集成或冲突解决改变了代码，必须重新验证。

### 4. 合回主工作区与冲突判定

将改动合回主工作区的永久分支：

- 尽量合并到已提交的历史部分，保护用户原有的未提交内容。
- **冲突裁决**：
  - **合入与主工作区未提交/暂存内容冲突**：**立即停机！** 保留现场并向用户汇报具体冲突文件，等待用户指令。
  - **无未提交冲突**：正常完成合并，并执行远端推送（`git push`）。

### 5. 清理交付

- 如果已知的所有任务步骤都已经完成了，请在推送成功后，移除临时 Worktree 与临时分支：

  ```bash
  git worktree remove ./my-project-tmp-<任务名>
  git branch -d tmp/<任务名>
  ```

- 如果明确知道还有后续步骤未完成，可按需保留临时 Worktree 与临时分支，并在确认全部完成后执行上一条的要求。
- 无论是何种情况，请确认主工作区停留在原永久分支，且用户原有的未提交修改完好无损，交付用户。

---

## 工作流 B：现成临时 Worktree 开发流

当且仅当当前已处于**独立的临时 Worktree + 临时分支**时触发：

1. **就地开发**：继承现有修改，直接在此工作区内编码，并按 `tenet-repository-test-gate` 完成提交前验证。
2. **本地提交**：验证通过后执行 `git commit`。
3. **就地交付**：严禁推送到远端，严禁合并回主分支，通知用户验收。
