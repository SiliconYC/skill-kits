# PyInstaller 体积优化

## 原则

- **不卸载、升级或修改现有 Python 环境的库**；不为缩包修改共享生产代码或牺牲功能。
- PyInstaller 不会无条件复制整个环境，但导入链、动态导入及 Hook 可能误收集大库；**先溯源，再排除**，不照搬黑名单。

## 执行

1. 记录旧版体积、文件数、构建参数；确认入口、平台、架构、图标及必要资源。
2. 查 `.spec`、构建日志、`xref-*.html`、`*.toc` 和 Hook，找出大文件由谁导入或收集；留意 `TYPE_CHECKING`、公共模块及动态导入。
3. 优先用 `.spec` 的 `Analysis(excludes=[...])` 排除已证实无关的模块；命令行构建可用 `--exclude-module`。原生库、Qt 插件和资源仅在确认无用后精细过滤。
4. 保留真正需要的动态驱动、Qt 平台插件、模板、样式和离线资源；冻结程序不能默认依赖开发环境的 `sitecustomize.py`。
5. **升级只留一个成品**：记录基线后，按用户要求在构建前删除旧版及确认属于本任务的重复产物；构建失败可能暂时无可用版本。不得误删源码、用户数据和其他软件。
6. 构建后实际启动，验证核心 GUI、文件操作、联网/离线、资源及退出；macOS 另查 ARM64、图标和签名。未实测的功能必须明示。
7. 清理无用中间目录，报告新旧体积、文件数、排除项、验收结果及剩余空间占用。

**停止条件**：功能完整、体积可接受即收口，不追求无休止缩包。

案例：接力打字板从 **809.2 MiB／4,390 文件**降至 **107.4 MiB／416 文件**，主要排除了无关的 QtWebEngine、地理信息和科学计算依赖；不能推断其他软件也有相同收益。
