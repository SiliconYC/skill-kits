# PyInstaller 体积优化

## 原则

- 不为缩包而卸载、升级或修改现有 Python 环境的库，不破坏共享生产代码或削减功能。
- PyInstaller 不会无条件打包整个环境，但导入链、动态导入和 Hook 可能收集无关依赖。先溯源，再排除，不照搬黑名单。
- 旧版、备份和构建产物的保留或清理由用户决定；未经授权不得删除。

## 执行

1. 确认入口、目标平台、架构、资源及构建方式；记录优化前体积和文件数。
2. 检查 `.spec`、日志、`xref-*.html`、`*.toc` 和 Hook，追踪大型依赖的真实收集路径，注意公共模块、`TYPE_CHECKING` 和动态导入。
3. 优先使用 `Analysis(excludes=[...])` 或 `--exclude-module` 排除确认无关的模块；原生库、Qt 插件和资源须逐项核实后再过滤。
4. 保留必需的动态驱动、平台插件、模板及离线资源；不要假定冻结程序自动继承 `sitecustomize.py`。
5. 实际启动并验收核心界面、文件操作、网络和退出；核对目标平台的架构、图标及签名。未实测内容如实标注。
6. 报告优化前后体积、文件数、排除依据与验收结果。功能完整且体积可接受时停止优化。
