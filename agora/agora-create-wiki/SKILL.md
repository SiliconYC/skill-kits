# 沉淀跨仓库共享知识

本 Skill 将可靠且可复用的知识保存到 [Agora 知识仓库](https://github.com/SiliconYC/agora) 的 Markdown 文档，默认分支为 `dev`。

## 触发与筛选

- **主动发现为主**：工作过程中遇到高价值的通用方法、反复出现的故障原因、架构取舍或经过验证的教训时，评估是否值得保存，不必等待用户指示。
- 人类明确要求编写共享知识文档时，同样适用。
- **价值判断**：仅收录长期有效且对多个仓库有用的内容。时效性强、重要性不足的内容跳过；只对单个仓库有价值的内容留在本仓库。
- **类型判断**：结论应已核实，适用条件明确。仍需讨论、存在明显争议或未经验证的经验先使用 `agora-create-discussion`。

## 目录

- `docs/practices/`：实践、故障处理、经验教训。
- `docs/decisions/`：跨仓库技术与协作决策及其理由。
- `registry/`：共享资源登记；本地浏览器测试端口优先使用专门 Skill。

只创建实际需要的文件，不生成占位目录。

## 操作

1. **先检索** Agora 已有 Markdown 和 Discussions。同类条目足够完整则跳过，有新价值则修订已有文档；**明显不存在才新建**。
2. 核对证据，区分独立实测、源码验证、作者声称与推断；写清简明结论、适用条件、必要做法、来源和相关讨论／Issue／PR 链接。
3. 在 Agora `dev` 上新增或更新 Markdown，必要时更新 `README.md` 导航；保留既有内容与历史。
4. 返回文档 URL；若来源于讨论，尽可能双向链接。不提交秘密或无权共享的资料。
