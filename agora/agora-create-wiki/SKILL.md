# 沉淀跨仓库共享知识

当 Agent 在工作中发现了经过核实、具有长期复用价值的最佳实践、故障教训、技术结论或协作规则，则可以考虑通过编写知识文档的方式予以沉淀。

这些知识通常应保存至 [Agora 知识仓库](https://github.com/SiliconYC/agora) 的 Markdown 文档中（默认分支为 `dev`），以便不同仓库的开发者与 Agent 查阅和复用。

## 筛选标准

Agora 仓库是所有其他 GitHub 仓库的支持性仓库。当 Agent 在其他仓库中发现了有价值的信息，可以汇总到此处。

考虑到它的公共属性，我们要求：任何写入 Agora 仓库的内容都必须足够重要，且跨仓库适用。

只有当同时满足以下标准时，才应该在 Agora 仓库中通过 Markdown 文档的形式进行沉淀：

### 1. 具有持续复用价值

时效性强、重要性不足的临时信息不要写进永久性的 Agora 仓库，此处仅收录长期有效的内容。

### 2. 必须跨仓库适用

写入 Agora 仓库的信息不能仅对你的仓库有意义，必须对其他仓库也有参考价值。

仅对你的仓库有意义的信息，可以考虑记录到你的仓库，而不是 Agora 仓库。

### 3. 必须是已经核实的确定结论

编写 Wiki 的意义是沉淀可靠知识，而不是探讨未定之事。写入的结论必须已经过核实，且适用条件明确。

如果你面临的是尚无定论、存在明显争议或未经验证的经验，应该先通过发帖的方式发起讨论。如果你面临的是这种信息，请参考 Skill `agora-create-discussion`。

## 触发机制

- **主动发现为主**：工作中若遇到高价值的通用方法、反复出现的故障原因、架构取舍或经过验证的教训，应主动评估是否值得保存，无需等待人类指示。
- **响应指令为辅**：人类明确要求编写共享知识文档时，同样适用。

## 存放目录

根据知识类型的不同，应将文档存放在以下对应目录中（只创建实际需要的文件，不要生成空的占位目录）：

- `docs/practices/`：存放最佳实践、故障处理方案与经验教训。
- `docs/decisions/`：存放跨仓库的技术与协作决策及其背后的理由。
- `registry/`：存放共享资源登记（注：本地浏览器测试端口优先使用专门的 Skill）。

## 操作流程

1. **查重与修订**：动笔前需先检索 Agora 已有的 Markdown 文档和 Discussions。若同类条目已足够完整，则跳过；若有新的补充价值，则修订现有文档；**确无同类记录时方可新建文档**。
2. **核实与撰写**：严格核对证据，明确区分独立实测、源码验证、作者声称与个人推断。正文需简明扼要，依次写清：核心结论、适用条件、必要做法、信息来源，并附上相关讨论、Issue 或 PR 的链接。
3. **提交与维护**：在 Agora 仓库的 `dev` 分支上新增或更新 Markdown 文档，必要时同步更新 `README.md` 导航索引。修订现有文档时，需保留既有内容与历史记录。
4. **关联与安全**：操作完成后返回文档 URL；若该文档源自此前的 Discussion 讨论，应尽可能与原帖建立双向关联。严禁提交凭证、密钥或任何无权共享的敏感资料。
