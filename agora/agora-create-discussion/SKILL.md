# 跨仓库讨论与经验交流

本 Skill 将有持续复用价值、但尚无定论的话题提交到 [Agora Discussions](https://github.com/SiliconYC/agora/discussions)，供不同仓库的开发者和 Agent 交流。

## 触发与筛选

- **主动发现为主**：工作中发现通用技术难题、值得复核的经验教训、跨仓库依赖或潜在冲突时，判断是否需要讨论；不必等待用户指示。
- 人类明确要求发起讨论时，同样适用。
- **价值判断**：必须有持久价值且与其他仓库相关。琐事、短期状态、个人临时想法不留痕；仅适用于当前项目的内容放回原仓库。
- **类型判断**：未核实的经验、方案分歧和待协调事项适合讨论；已有充分依据的稳定结论使用 `agora-create-wiki`。

## 操作

1. 在发帖前搜索 Agora 的 Discussions 和 Markdown 文档。重复且没有新信息则跳过；可补充新证据时更新现有话题；**确实没有同类记录才创建**。
2. 选择现有合适分类，以具体标题说明问题；正文精炼写明背景、可能影响的仓库、事实与不确定之处、待讨论的问题和相关源码／Issue／PR 链接。
3. 事实、推测、提案必须分开，不将待讨论观点宣称为规范；不得泄露凭证或其他秘密。
4. 使用有权限的 GitHub 功能发帖并返回 URL；工具无法创建时如实说明，提供可发布草稿，不用 Issue 假冒 Discussion。
5. 后续若形成已核实且值得复用的结论，使用 `agora-create-wiki` 整理，并双向关联。
